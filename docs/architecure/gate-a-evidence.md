# Gate A evidence — Linux, 2026-09-09

Status: automated subtests passed; full physical-device acceptance pending. PR: none; unmerged local work.

Host environment: Linux, Chromium 153.0.8010.12, extension 0.1.0, native adapter `youtube-native-v0.1.0`. An isolated browser profile loaded the actual built extension against regular `www.youtube.com/watch`. The service and QR origin was `http://192.168.1.84:8787`.

| Scenario | Observed result |
| --- | --- |
| Consecutive transitions | 20/20 confirmed with fullscreen, overlay, original player, and expected video identity retained |
| Repeated video | Alternating pairs of `jNQXAC9IVRw` and `aqz-KE-bpKQ`; separate attempt IDs and restart evidence |
| Pause/resume | Server observed paused, then playing |
| Skip | Confirmed stop returned to intermission |
| Completion | Seeked near the end, then observed the actual ended event and intermission |
| Unexpected native load | Detected out-of-sync; did not assign the selected singer to the new video |
| Unavailable video | `00000000000` produced blocked state, no load evidence or singer attribution, and preserved fullscreen/overlay |
| Guest queue | LAN browser joined as Jamie and submitted `jNQXAC9IVRw` for Jamie; room queue showed `pending` with requester derived from the participant credential |

The run had 22 confirmed transitions in total because completion/native-change scenarios loaded additional performances after the 20-transition sequence. The deliberate unavailable-video scenario ended in `blocked`; that is the expected scenario result, not a failed test run.

Evidence was generated by `npm run gate:live` and stored locally in `artifacts/gate-a-live.json`. The runner polls resolved server state with assertions, rather than treating asynchronous page predicates as proof. An earlier polling implementation was corrected before this recorded scenario result.

This does not verify an actual phone camera/QR scan, the host's signed-in/Premium profile, Windows, iOS Safari, Android Chrome, a two-hour session, or production reconnect/rebinding. Unknown player states and cross-tab isolation are covered by separately labeled controlled tests.
